# Windows 面板：操作方法与顺序

本指南同时解释早期 Tk 面板与新的 WPF 面板。检测算法、模型 ID、配置键和历史记录格式不因界面改变。
源码与统计边界见 [原理分析](ANALYSIS.zh-CN.md)，安装见 [WINDOWS.md](WINDOWS.md)。
界面示意图：[主界面](windows-native-main.png)、[展开详情](windows-native-detail.png)、[设置页](windows-native-settings.png)。
示意图使用合成数据；演示模式不会发起模型推理。

## 先理解三种操作

| 操作 | 做什么 | 是否发起模型推理 |
| --- | --- | --- |
| 刷新 / 诊断 | 读取本地状态、会话与安装信息；诊断可检查私有 app-server 连接 | 否 |
| 检测某个会话 | 在该会话的临时 fork 中采集回答，沿用它的模型与推理力度 | 是 |
| 新会话检测 | 用新建的临时会话检测当前默认模型或本次指定模型 | 是 |

`Queries` 是每次检测要采集的回答／fork 数，范围 1–3，不是自动检测次数。
后端可能因超时或无效回答补采和重试，所以样本数量不是固定 token 账单。
一份有效回答可作初探，但强不匹配裁决需要至少两份有效回答；三份也不保证真实归因准确率。

## 推荐顺序：先手动，再决定是否自动

1. **启动和诊断。** 发行版双击 `IsGPTNerfed.exe`；源码模式运行 `launch.cmd`。
   查看 hooks 是否已信任、Codex 是否加载插件。
   有异常时点“诊断”，按输出修复。首次安装／信任后需要重启 Codex。
2. **设置检测方式。** 进入“设置”，先把“每个活跃会话”和“独立新会话检测”都设为“手动”，
   “会话到期时”选“仅提醒”，“每次检测的样本数”建议先保留“3 份”，点“保存设置”。这不取消已发出的推理。
3. **检测已有会话。** 回到会话列表，找到目标标题并核对模型／力度，点该卡片的“检测”。
   会话进入运行状态后不要重复点同一个目标。可以继续刷新、查看其他会话或进入设置页。
4. **查看结果。** 点会话标题展开，先看最新有效裁决，再看模型归因、历史和被动证据。
   必要时“复制报告”。一条新的失败记录不会把之前有效裁决改成失败；两者要分开读。
5. **只在失败后重试。** 查看失败原因，再点“重试”。重试会再次采集样本并使用额度。
6. **需要对照时检测新会话。** 在独立的新会话区域操作。“模型”和“推理力度”留空表示跟随后端默认值；
   指定值只覆盖本次新会话检测，不修改 Codex 的模型设置，也不改变已有会话。点“查看报告”展开新会话结果。
7. **最后决定调度。** 如只要到期提醒，将“每个活跃会话”设为时间或轮数（例如 `30m`）、
   “会话到期时”选“仅提醒”，“独立新会话检测”继续“手动”。如需后台检测，再把“会话到期时”
   改为“后台检测”；新会话自动检测另行选择频率，最后点“保存设置”。

会话时间间隔按上次检测／提醒或创建时间计算墙钟经过时间，并在近期有 hook 活动时检查，
不是累计实际工作分钟数。新会话的时间调度独立于旧会话活动，也独立于会话的“仅提醒”选项。
当前账号尚无新会话检测历史时，启用新会话的时间调度可能立即满足到期条件，而不是先等待一个间隔。

## 原截图中各控件的含义

源码包中的旧 Tk 面板可通过 `launch.cmd --legacy-tk` 打开，需要另装带 Tcl/Tk 的 Python。

| 原控件 | 操作与含义 |
| --- | --- |
| `Sessions and status` | 点击普通会话行选中目标；右侧显示该会话的文本报告。`Fresh session` 是特殊行 |
| `Probe selected` | 检测选中的普通会话；选中 Fresh 行时不能用它发起新会话检测 |
| `Retry selected` | 与 `Probe selected` 调用同一个 `worker --thread` 入口；旧界面没有严格按失败状态区分 |
| `Fresh model` / `Effort` | 仅传给下一次 `Fresh probe`；留空使用后端默认值，不需要点 `Apply settings` |
| `Fresh probe` | 发起独立的新会话检测，不以当前选中的普通会话为上下文 |
| `Frequency` | 普通会话的检测间隔；`manual`、`30m`、`1h`、`turns:8` 等 |
| `Mode` | `auto` 到期后台检测；`nudge` 只在会话 hook 中提醒用户 |
| `Queries` | 每次检测的回答／fork 数，1–3 |
| `Desktop notifications` | 是否启用通知；原 Windows 版通过运行中的托盘面板显示气泡 |
| `Sound on downgrade` | 是否在降配信号时播放提示音 |
| `Hide session titles` | 隐藏展示标题和账号，用于截图；不删除保存的原始记录 |
| `Apply settings` | 保存以上六项设置；旧面板不包含 `fresh_frequency` 控件 |
| `Refresh` | 读取快照，不会因点击刷新本身发起指纹推理 |
| `Doctor` | 环境诊断；输出显示在旧版右侧文本区域 |
| 窗口右上角关闭 | 托盘可用时隐藏窗口，面板和调度仍运行；托盘中 Quit 才退出面板 |

截图里的 `Running probe...` 是旧面板正在等待检测命令返回，所有操作按钮会暂时被其全局忙状态禁用。
它不提供精确百分比或服务端进度。报告里的 `tick: nothing due` 是更早的一次调度检查输出，
意思是当时没有需要启动的普通会话检测，不是“模型匹配”或本次检测失败。
新面板把这种操作状态与会话证据分离，长检测不再锁住刷新和页面导航。

若继续使用旧面板，并希望普通会话与新会话都只手动检测，可在终端设置：

```powershell
.\bin\nerfed.cmd config set frequency manual
.\bin\nerfed.cmd config set fresh_frequency manual
.\bin\nerfed.cmd config set mode nudge
```

## 如何读裁决

| 展示状态 | 应如何理解 |
| --- | --- |
| 匹配 | 当前数字指纹第一候选与声明模型一致；只适用于当前库能比较的模型，并非服务端身份认证 |
| 无法区分 | 声明 Astra 或 Sol 6.1、原始候选为 Astra；当前指纹不能可靠区分两者，中性显示，不据此告警或暂停 |
| 降配／升配／改路由 | 达到门槛的不匹配，或会话日志中的相应变化；展开查看究竟是哪一种来源 |
| 可疑 | 有差异但证据不足，不能直接下强结论 |
| 待验证 | 账号变化或历史账号未知；旧结果不能替当前账号背书 |
| 尚未检测 | 没有可用裁决；不是“匹配” |
| 未收录 | 声明模型不在当前模型库中，缺少直接比较对象 |
| 无效／失败 | 无可用样本、工具／拒绝／传输等问题；查看失败详情，不能解释成降配 |
| 已到期 | 调度条件满足，不代表已经检测，也不代表结果异常 |

旧列表里的 `ACTIVE` 只表示近期有 hook 活动，`QUIET` 表示近期不活跃；它们不是检测结果。
模型归因百分比只在模型库候选集合内比较，不能直接证明服务端权重或通用能力变化。
用户真实标题、模型 ID 与原始证据不会被自动翻译成其他含义。

从 port.5 起，展开详情依次核对“声明模型”“指纹”“被动告警”。若同时看到
“Astra / Sol 6.1 · 无法区分”和“推理强度变化告警”，前者是本次数字指纹的能力边界，
后者来自会话日志，应核对具体变化与时间。旧事件可能早于本次检测，不应把它当成
数字指纹刚确认了换模型。旧裁决保留在历史中，展示层按当前规则解释，不删除证据。
依据、复现与后续校准条件见 [指纹可靠性分析](FINGERPRINT_RELIABILITY.zh-CN.md)。

## 关闭、退出与更新

关闭窗口可保留托盘；从托盘或面板“退出”结束面板。退出面板不会卸载插件，Codex 的 hooks
仍按保存的配置运行。需要停止后续自动检测时，先将两套频率设为手动，再保存。
已经发出的服务端推理不能仅凭窗口关闭就假定已取消。

更新后重新运行 `launch.cmd` 才会使用新前端；已经打开的旧 Tk 窗口不会自动换成 WPF。
编译便携版应从新解压目录运行 `IsGPTNerfed.exe`，并保留同目录 DLL、运行时和插件文件。
若安装时使用的运行时路径改变，需要从新目录重新安装并检查 hooks 信任。
仅替换前端且 hooks 命令未改变时，可保留已有信任；重装生成的命令改变时，按 Codex 提示重新审阅。
不需要重置历史。不要同时开两套正式面板以免重复运行调度器。
